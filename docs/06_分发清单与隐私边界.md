# 分发清单与隐私边界

## 放进公开仓库

源代码、通用安装工具、去个人化示例、中文文档、测试、版本记录、版权与许可证。公开技术规则只约定接口、隔离、偏好、记忆预算、点歌确认、失败提示和维护流程。

## 放进两个离线附件

允许分发的固定版本模型、引擎源码、便携 Node/Python、隔离依赖、编码器与必要的第三方原始归档、完整许可证和安装指引。使用者仍须提供自己的素材和宿主程序。

今天的声音附件约 27.6 GB、QQ 桥附件约 76.7 MB，按十进制字节计算。源码仓不把这些 ZIP 提交进 Git；发布附件是否适合某个平台的单文件上限，发布时另查当前限制。

Vevo2 原权重、NapCat 原始归档带有限制；打包分发必须遵守原文，不能包装成无限制商用资源。二次修改权重的分发与生成媒体使用是不同问题，需要分别核对许可。

## 本机保留，不公开

- 真实 QQ/B站号、访问令牌、Cookie、扫码状态、会话目录与密钥。
- 私人角色规则、聊天、SQLite 记忆、语音输入和输出、试听、参考声线及其个人选择记录。
- 私人歌曲原件、批准片段、歌单、训练数据、LoRA/其他训练结果。
- 含上述信息或绝对私人路径的旧施工记录、审计日志和迁移收据。

历史记录与人设归档在 `本机私有/`，但原系统的账号凭据、聊天数据库和媒体未因这次整理而复制过来。旧运行现场继续独立保存。

## 目录规则

`本机私有/`、`本地资源/`、`发行包/`、`构建产物/`、`*.local.json`、数据库、音视频和权重默认被 Git 忽略。构建仅取当前公开源码和明确许可的干净资源白名单，不从本机私有目录取输入。

忽略不是加密，也不是权限隔离。不要用 `git add -f`，不要把根文件夹整体作为压缩包或网盘目录发出去。公开源码应以 Git 跟踪清单为准，离线 ZIP 应以已验证的发行目录为准。

## 发布前操作

运行 `.\维护.ps1 check`，检查待提交文件和本机私有模式；检查 `git status` 与 `git ls-files`，确认忽略目录没有被跟踪。再核对附件的 SHA、CRC 和逐文件清单。通用检查和已知模式扫描不能证明发现一切未知秘密，新增配置仍需人工审阅。

本仓没有放入公共模型 API 账号，也不会代替使用者注册 QQ、B站账号或写私人角色性格。安装工具提示他们填写自己的内容。
