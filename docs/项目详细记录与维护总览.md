# 项目详细记录与维护总览

## 一、我们要做成什么

把“听懂用户语音—交给 DSH 理解—用本地声音回复”做成可给别人安装的能力。使用者可以保留自己的平台桥和角色规则，也可以采用我们整理的独立 QQ 桥。两个产品分开交付，互相通过接口连接。

本阶段只维护声音、聊天接入、点歌和有预算的本地记忆。虚拟形象、表情和嘴型同步不放进当前产品。

## 二、交付形式

1. **通用声音离线包**：DSH 插件、本地服务、语音识别与合成工具、参考声音克隆、可选 LoRA 训练和 Vevo2 歌声转换流程，以及允许分发的便携运行环境、模型、许可证。
2. **独立 QQ 桥离线包**：整理后的 DSH OneBot 桥、安装工具、原始 NapCat Framework 归档、登录和白名单指引。使用者自己准备 QQ 号、DSH 模型配置和角色规则。要听说能力，再接声音包。

“离线”指声音依赖与模型随包提供、声音可本地计算；QQ 联网和用户选择的云语言模型仍然需要网络。宿主 DSH、官方 QQ 客户端和显卡驱动属于使用前提，不能假装包内已经代替这些程序。

## 三、完整链路

用户文字或语音进入平台桥。文字直接进入 DSH；语音先下载并转成识别文本。桥将本轮输入、有限记忆和当前输出偏好交给 DSH 原生会话。DSH 生成与上下文相符的回复，再按持久化偏好发送文字，或调用本地合成服务取得音频后发送语音。

点歌另走“审核歌单—匹配歌曲/长短—轮换片段—发送音频”的确定流程，不让语言模型虚构音频，也不在每次点歌时重新训练。歌词、旋律和歌声转换的来源，由使用者自己的素材决定。

上下文太长时，先把来源可追溯的摘要和重要点留在本地，再在安全时机新建 DSH 会话。新会话读有限摘要；需要细节才检索本地记录，避免每轮把完整历史再次发送。

## 四、用了哪些东西

| 作用 | 当前技术 | 维护位置 |
| --- | --- | --- |
| 对话理解、原生会话 | 使用者现有 DSH 与其语言模型 | 宿主配置，不内置私人凭据 |
| QQ 传输 | 上游 OneBot 桥整理版 + NapCat Framework | `packages/qq-bridge` |
| 通用声音接口 | 本地 HTTP 服务和 DSH 服务对象 | `packages/voice/plugin` |
| 语音输入 | Whisper 本地识别 | 声音包模型/运行环境 |
| 参考声音说话 | VoxCPM2，另有 Qwen3-TTS Base 路线 | 声音包工具与模型 |
| 真正的可选微调 | VoxCPM2 LoRA | 素材准备脚本、训练模板、官方训练源码 |
| 把已有演唱转成指定音色 | Vevo2 | `tools/convert-vocal.py` |
| 记忆/点歌/偏好 | Node、SQLite 与本地文件 | `shared` |
| 便携环境 | Node 24.20、Python 3.11/3.12 及隔离依赖 | 被忽略的 `本地资源` |

## 五、使用者从零怎么做

1. 准备自己的 DSH，先确认语言模型能正常聊天。
2. 准备一位说话者的干净参考声音；先做短句克隆试听，确认选中哪一个文件。不要自动混用不同候选声线。
3. 解压声音离线包，按文档生成自己的本地配置和令牌，再安装到实际使用的 DSH profile。
4. 保留已有平台桥时，按声音包接口适配输入识别、输出合成；采用独立 QQ 桥时，准备角色号和聊天号，扫码登录并配置同一套 OneBot 参数。
5. 按文字、语音输入、语音输出、语言保持、连续聊天、记忆换会话逐项测试。
6. 想进一步训练时，再整理转写、切片和训练/验证集合，单独启动 LoRA。模型训练不是安装时自动执行的步骤。
7. 想唱歌时，用自己的干净演唱人声进行转换，试听后审核片段并导入歌单。之后“唱长一点/短一点”调用已审核片段。

## 六、规则放在哪里

技术规则在 AGENTS.md、共享源码和这组文档中；各产品的 README、安装指引和示例配置负责引导使用者填写自己的参数。角色性格、人设、关系和个性规则由使用者自己写。

本机历史规则为维护留档，单独放在 Git 忽略的 `本机私有`，不注入通用包。私人的音频、歌单、训练结果、账号和聊天不进入发行产品。已选素材继续由原运行现场使用，本次不改其路径。

## 七、版本以后怎么修

以后从本目录开分支，修改组件或共享模块；同步共享代码，跑离线回归，再做受影响的真实功能验证。变更插件版本后构建候选包，核对隐私、许可、安装和 SHA，最后才发布。

今天的两个 ZIP 为不可变基线；新的候选进入 `构建产物`，确认后才归入新的发行日期目录。不要覆盖同版本包，也不要把整个本地维护根目录压缩发出去。

## 八、当前证据怎么理解

已完成的离线检查、依赖导入、DSH schema 加载和 ZIP 校验说明安装链路与程序结构得到验证；它们不能替代目标电脑音质、GPU 推理、长期聊天和训练收敛验收。每次更新需把实际运行的检查和仍未运行的项目分开记录。

详细方法继续读编号 01—06 文档；简短口播提纲见 `视频文案要点_简版.md`。
