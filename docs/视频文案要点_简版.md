# 独立 QQ 桥与声音训练包：视频文案要点

这套系统的大方向：让 **DSH 负责理解和思考，QQ 桥负责收发消息，本地声音模型负责听和说，本地记忆负责衔接长时间的聊天**。

## 一、主要用了哪些东西

| 工具 | 作用 |
|---|---|
| DeepSeek Harness（DSH） | 连接聊天模型，理解消息、组织回答、管理会话 |
| NapCat＋OneBot | 把普通角色 QQ 接到 DSH，实现消息收发 |
| Whisper | 在本地把收到的语音转成文字 |
| VoxCPM2 | 主要说话引擎，用参考声音生成新句子，也提供 LoRA 微调路线 |
| Qwen3-TTS | 备选的声音克隆模型，用来对比和选择效果 |
| Vevo2 | 把已有演唱人声转换成选定的音色 |
| SQLite 本地记忆库 | 保存聊天、重点和摘要，需要旧事时再检索 |

## 二、整个流程一步步怎么做

### 第一步：先把聊天接通

准备角色专用 QQ，通过 NapCat 和 OneBot 接到 DSH。先确保普通文字聊天正常，再往上增加声音功能。

### 第二步：准备并选定声音

找干净、清楚、只有一个说话人的音频，去掉背景音乐和别人插话的部分。先做几条试听，对比清晰度、自然程度和音色，选好后固定参考声音，后续一直使用同一条。

### 第三步：让它用这个声音说话

主要使用 VoxCPM2，也用 Qwen3-TTS 做备选对比。把 DSH 生成的回答交给本地声音模型，再调整音量、气息和机械感，逐步筛选效果。

这里要说准确：**参考克隆是用基础模型配合参考音频生成声音；真正的 LoRA 训练会产生新的训练权重。** 有足够素材时，再进行分段、核对文字、划分训练和验证数据、微调、对比试听，合格后才采用。

### 第四步：接上语音聊天和模式切换

收到语音后，先由 Whisper 转写，再让 DSH 理解和回答。用户要求打字，就发文字；要求语音，就把当前回答合成声音发回 QQ。语言和回复模式会持续保存，直到用户明确切换。

### 第五步：做唱歌和点歌

提供歌曲的演唱干声，用 Vevo2 配合同一条声音参考转换音色，保留原来的歌词、旋律和节奏。然后试听、标时间，把好听的片段留下来，加入本地歌单，支持点歌、换歌、长短片段选择。

**目前这条唱歌路线是“歌声转换＋播放已选片段”。点歌时播放保存好的成品，不需要每次重新生成整首歌。**

### 第六步：加入长期记忆，控制上下文长度

把聊天和明确要求记住的重点保存在本地。聊到一定程度，就整理简短摘要、保存衔接信息，再换一个新的模型会话。新会话只读少量必要内容，遇到较早的细节再搜索本地记录，减少长聊历史不断堆积带来的 token 消耗。

当前摘要采用本地原话摘录整理，不额外调用模型生成摘要。

### 第七步：分成两个包给别人使用

- **通用声音包**：提供声音识别、合成、训练方法、歌声转换、基础模型和离线依赖。已有 QQ、B站或其它桥的人，可以保留自己的接法，按接口说明接入声音能力。
- **独立 QQ 桥包**：给从头搭建的人使用，负责连接角色 QQ 与 DSH，并接好文字／语音切换、记忆和点歌，再配合通用声音包工作。

嫁接的原则是：**平台连接归桥负责，声音处理归声音包负责，角色规则和个人资料归使用者自己管理。**

分发时只提供通用能力、基础模型、依赖和说明；我们的账号、令牌、聊天、个人规则、参考声音、歌曲和训练产物都不放进去。使用者提供自己的账号和素材，再完成自己的配置与试听。使用和分发遵守各组件许可，部分组件限非商用。
