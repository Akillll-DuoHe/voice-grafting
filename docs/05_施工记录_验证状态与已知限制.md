# 施工记录、验证状态与已知限制

记录日期：2026-11-01。以下是去除私人账号、素材和聊天后的工程记录。

## 需求演进

1. 最初探索 QQ 角色聊天与本地声音，后来确定以 DSH 插件交付，不做另一个独立聊天程序。
2. 从官方机器人路线转向角色专用 QQ + NapCat / OneBot。已有桥和声音服务分离，以便其他人复用。
3. 增加语音输入识别、按当前上下文回复、文字/语音持续切换和语言持续设置；语音输出不额外附中文翻译。
4. 声线经过多轮试听选择，教训是必须锁定实际选中的文件及 SHA，不能把名称相近的参考替代为相同声音。
5. 唱歌改为对现有演唱做音色转换，再把人工批准片段登记到本地歌单。长短筛选与按歌曲轮换用于后续点歌。
6. 记忆改为本地记录、有限摘要、按需检索与 DSH 会话安全轮换，避免每轮加载全历史。
7. 收敛为两个干净离线包：通用声音和独立 QQ 桥。形象、表情、嘴型不纳入此版本。
8. 本次建立长期维护仓，把公开源码、私有施工记录、干净资源和已完成 ZIP 分开。

## 已处理的工程问题

- Windows CMD 参数不能拼成一个字符串交给安装器；入口使用 PowerShell 数组展开，路径含空格时仍逐项传递。
- vendored `ws` 的 ESM 调用使用其 wrapper，避免从 CJS 入口读取不存在的命名导出。
- Python 运行环境按引擎分开；修正离线便携环境内的 protobuf 兼容和 Vevo 所需 parselmouth 依赖，并保留第三方许可/源码。
- 同版本 TGZ 更新可能命中旧缓存，后续通过递增版本保证可识别升级。
- 点歌游标必须在发送确认后提交；片段多的歌曲不能挤占其他歌曲机会；空库、未知曲名或长短不匹配应明确返回。
- 会话轮换前保存本地记忆，新会话创建失败保留旧映射；跨聊天事实和检索预算须隔离。

## 仍需验收的部分

- 新包在目标电脑的 GPU 合成、识别/转换速度、显存峰值和声音主观质量。
- 自己素材上的 LoRA 训练收敛和留出集效果。
- 真实 DSH 长时间聊天触发轮换后的相关回忆与费用走势。
- 第三方平台桥的音频格式、接入钩子、权限与失败重试；B站需要专门连接器。
- 情绪和真实笑声自然度、歌唱高音一致性；不同模型之间无法只靠相同参考文件保证完全一致。

本次整理不启动训练或媒体生成，也不以私人在线系统的历史试听代替公共包的跨机测试。
