# 声音素材、克隆、训练与唱歌

## 先把三件事分开

**参考声音克隆**：给 VoxCPM2 或 Qwen3-TTS Base 一段参考声音，让其用类似音色读新文字。通常不需要重新训练权重。试听认可后，锁定参考文件与 SHA，防止以后误用其他候选。

**LoRA 训练**：整理同一说话者的多条干净声音与人工核对的文字，运行训练，产生适配权重。它可能改善一致性，但效果受数据、训练设置和设备影响，不能用安装成功代替训练成功。

**歌声转换**：把已有演唱人声的内容和旋律交给 Vevo2，以指定参考声音转换音色。它不是文字直接生成任意歌曲，也不是把歌曲永久“学进”说话模型。已转换并审核的片段可直接放入点歌库。

## 使用者需要提供什么

| 内容 | 建议 |
| --- | --- |
| 参考声音 | 单人、清楚、稳定、无配乐/混响/电流/喷麦；保留原始文件，优先无损 WAV |
| 更完整的训练素材 | 同一说话者多条不同文本和语气；避免混入其他人的声音和强处理成品 |
| 转写 | 每段真实说了什么，人工核对人名、语种、漏字和重复；文件与文字一一对应 |
| 训练/验证拆分 | 按原录音来源分组，不能同一长录音相邻切片同时混入两组 |
| 唱歌素材 | 有权使用的干净演唱人声；需要时自行提供伴奏，先做人声结果再混音 |
| 本机配置 | DSH 可正常聊天、可用显卡/驱动与磁盘、自己的参考路径、账号和角色规则 |

不要把参考声线、作品台词、录音或演唱素材的使用授权等同于模型代码许可证。公共包不附带作者的私人声音、歌曲或训练成果。

## 一、先跑短句，不急着训练

1. 解压通用声音离线包，按 README、解压说明检查路径与空间。
2. 用 `安装配置.cmd` 填写自己的参考 WAV、DSH CLI 和实际 profile。会生成自己的配置与随机令牌。
3. 先运行环境检查，再使用短句试听，检查清晰度、音量、底噪、破音、停顿和语言。
4. 把候选文件分开命名，人工选择一个后记录路径与 SHA。不要用上游原参考或旧批准结果替代本次实际选中的输出。
5. 再接平台文字转语音与语音转文字。先确认内容正确，再调音色和音质。

默认说话路线是 VoxCPM2；Qwen3-TTS-12Hz-1.7B-Base 是另一套可单独测试的路线。三套引擎按需先后运行，不要求同时占用显存。切换自己的任务前应确认资源，不得为此停止用户其他模型。

## 二、真正训练 VoxCPM2 LoRA

1. **收集与保留原件**：按说话者、来源整理，复制工作副本，不覆盖原音频。
2. **清洗切片**：去掉静音过长、多人重叠、音乐、强混响、严重噪声及破音。单片优先约 3—30 秒，句子完整；最终依训练脚本限制核对。
3. **转写复核**：ASR 可做初稿，但训练前人工校对，声音和文字必须一致。
4. **建立清单**：使用 `audio,text,speaker,group,split` 等字段；来源组隔离训练/验证集，重复 PCM 需要检查。详细格式见产品 `docs/素材与训练.md` 和准备脚本帮助。
5. **生成训练数据**：运行声音包的 `prepare-training`；查看输出报告，处理缺文件、无效音频、重复和文本不匹配。
6. **检查训练配置**：以 `plugin/training-guides/voxcpm2-lora.example.yaml` 为模板，填自己的基模、数据、输出目录、批量、步数等；参数根据显存实测，不保证统一配置适合所有机器。
7. **单独开始训练**：`train --config 你复核后的配置.yaml` 调用随包的官方训练源码。训练由安装者主动启动，不在安装时后台开始。
8. **对比与保留**：用没参加训练的文字和声音验证，比较基模克隆与 LoRA。保留 checkpoint 和 `lora_config.json`，通过自己的后端 `lora_weights_path` 加载。
9. **验收后启用**：听感、发音、情绪、长句、不同语种分别测试。记录数据版本、参数、权重 SHA 和结论；失败不覆盖已认可的参考方案。

具体命令以包内 CLI 和官方训练模板为准。当前交付提供训练链路和依赖，不含作者已训练权重，也没有宣称在所有显卡上完成训练收敛验证。

## 三、唱歌怎么做

1. 选自己的歌曲音频/视频，提取干净演唱人声。多人、男女合唱要先隔离目标段；说话参考没有覆盖的高音、嘶喊更容易出现机械音和破音。
2. 先挑音域合适、平稳且清楚的片段。不要把大段静音留在开头；严格按人工指定的时间范围剪取。
3. 调用 Vevo2 转换，参考使用已锁定的同一声线。当前工具采用分块和重叠衔接，实际参数在 `tools/convert-vocal.py`，不是为每首歌训练一个新模型。
4. 单独试听人声，检查电流声、辅音、音量、片段衔接和高音。不要只靠提高增益掩盖破音。
5. 有需要再与自己的伴奏混音；用户只要人声时不加伴奏。
6. 按片段登记曲名、来源区间、实际时长、文件、SHA 和人工批准状态，使用 `tools/register-songs.py --approve` 导入自己的歌单。
7. 平台点歌直接调用库里的已批准音频。先选歌曲再选片段，避免片段多的歌曲占满随机机会；先排除最近歌曲，再轮换片段。

“长”默认不少于 30 秒，“短”低于 30 秒；没有匹配结果就明确提示，不偷偷换成别的长度。发送得到平台确认后才推进游标；失败重试保留选择。没有歌单时引导配置，不声称正在唱歌。

## 四、音质、情绪和局限

参考素材和源演唱决定了质量上限。过强去噪会损伤齿音与高频；过大增益会使喷麦、底噪更明显。先确认源文件是否干净，再分别调整合成参数、呼吸/低频处理和响度，逐次对比。

开心、低落、轻笑等需要素材或引擎支持。把“哈哈”写进文本并不保证是真实笑声；说话音色相同也不意味着歌唱高音自然。当前歌声转换和说话合成是不同模型，仍要人工验收一致性。包内没有表情图片、虚拟角色或口型模块。
