# 本地记忆与上下文规则

## 目标

把长期记录留在本机；模型每轮只读取必要部分。上下文达到阈值后继续聊天时安全换新 DSH 会话，让 token 开销有预算。检索能找回已保存内容，但不承诺所有历史都准确记住或记忆完全不消耗 token。

## 保存什么

每个聊天使用独立键，保存事件、明确要求记住的重要点、会话轮次、摘要与轮换记录。SQLite 默认在桥数据目录的 `qq-long-memory/memory.sqlite`；策略配置在同目录。原始平台日志与 DSH 原生记录是其他存储，不等于这一个记忆库。

摘要采用本地摘录与引用，保留原消息来源、时间；不是再调用一次云模型做语义总结。明确的“记住/记一下”等可写入重要点，普通聊天并不全部自动升级为永久人设。

## 每轮怎么读

1. 确认聊天白名单与事件来源，拒绝陌生人和注入测试请求污染真实记忆。
2. 读取有限重要点、最近会话摘要与最近消息。
3. DSH 需要旧细节时，调用本地 `qq_memory_search`；返回少量有来源的相关结果。
4. 拼入当前会话的有限上下文，不把整个数据库或所有历史文件重新发送。

“本地”描述存放位置；如果 DSH 用云模型，被本轮选中的记忆片段仍会随请求发往该模型提供方。它不代表全链路离线。

## 默认预算

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| maxSessionInputTokens | 12000 | 会话输入估算阈值 |
| reservedTokens | 3000 | 给当前输入、系统和工具等保留余量 |
| maxMemoryTokens | 2200 | 注入记忆总体预算 |
| summaryTokens | 600 | 摘录摘要预算 |
| retrievalTokens | 700 | 检索结果预算 |
| maxTurns | 24 | 会话轮数阈值 |
| maxAgeMinutes | 90 | 会话年龄阈值 |
| recentMessages | 8 | 最近消息数量 |
| maxSearchResults | 4 | 一次最多检索结果 |
| 每轮搜索次数 | 2 | 防止模型无限检索 |

前十项字段名与 `shared/local-memory.mjs` 的 `memoryDefaults` 一致，可在自己的 `qq-long-memory/policy.json` 中按校验范围调整；每轮两次搜索由桥的工具注册逻辑限制。修改后先做回归，再观察真实会话预算。

有宿主实际 usage 时优先使用；没有时按 UTF-8 字节数除以 2 等保守估算。此预算不是精准账单，也不是对所有宿主附加提示词的绝对 API 上限。超长当前输入仍需独立输入限制。

## 达到阈值怎么接着聊

在下一条可安全处理的输入处检查轮数、时长和估算 token。若旧会话正在处理，先遵守队列，不在输出中途硬切。将摘录摘要、重要点和来源写入本地后，创建新的原生 DSH 会话，注入预算内记忆，再切换路由。

新会话创建失败则保留旧会话映射和本地事实，避免“换窗失败把之前的东西也丢了”。明确说“换个新上下文，之前的别忘”同样保留本地事实。输出语言、文字/语音模式、点歌游标独立保存，不依赖模型临时记住这些开关。

## 维护与验收

- 优先备份自己的数据库和策略，再改变结构或迁移；不能把旧测试数据、停用桥的数据和新聊天身份盲目混合。
- 测试跨会话事实、旧记录检索、不同聊天隔离、搜索上限、轮换失败和偏好持续性。
- 离线测试通过只证明模拟条件下的行为；还要在真实 DSH 中连续聊天并观察 usage、轮换与回忆。
- 删除一个事实不等于彻底删除平台日志、DSH 记录和历史备份；完整删除功能需要覆盖这些存储，当前不作这种承诺。
- 通用声音包附带记忆模块源码，第三方桥须接入自己的会话生命周期；并非装上 ASR/TTS 就自动具备整套记忆。
