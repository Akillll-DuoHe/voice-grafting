# 本地记忆与上下文预算

原始聊天和语音转写留在使用者本地 SQLite。近期记录、明确要求记住的重点、来源时间及会话映射分别保存。每次只加载有限记忆；旧事由只读搜索工具按需查找。

默认参数：会话输入目标12000估算token，系统/工具预留3000，注入记忆最多2200，摘要600，单次检索700，最多4个检索结果、每轮最多2次工具检索；24次入站或90分钟兜底轮换。参数保存在自己的 `qq-long-memory/policy.json`。这里的估算不是平台账单：能取得本轮 usage 时使用 usage，缺失时按文本字节保守估算。工具定义等宿主固定成本以及单条输入上限仍需按实际模型调整，不能承诺每次API请求恰好低于某个token数。

临近预算→在本轮结束后的下一次输入前保存带来源的摘要→建立新原生 DSH 会话→注入受限摘要/重点/近期记录→切换路由。新会话创建失败时保留旧路由，不删除记忆。摘要使用本地原话摘录，零额外模型调用；它不等同于模型的语义概括，较早的细节仍靠原文检索。每代摘要另存到本地会话子目录，原始事件长期可查。

自然命令：“记住我喜欢……”保存重点；“记住这个”引用上条用户消息；“查看记忆”列重点；“换个新上下文，之前的别忘”安全换会话。“忘掉/彻底删除”未在此版作为完整隐私删除承诺，DSH 原日志和备份需由使用者另外处理。用户纠正优先于旧记录，历史数据不会被当作执行指令。

语言、文字/语音模式和歌单游标独立持久化，不靠摘要记住。模型是云端时，选中的相关记忆仍会随请求交给模型；本地保存不表示模型请求完全离线。

现有第三方桥可导入 LocalMemory：在自己的数据目录 new LocalMemory(cwd)；只在真实授权输入/成功输出后 record；新建或续接会话后 bind；交接前 due→prepareRotation→创建新会话→activate；新会话注入 context；注册只读 search 工具并设每轮次数上限；释放实例时 close。不要把未经授权的群成员、回放或注入调试帧写为个人事实。配套QQ桥已实现这些钩子，见 plugin/lib/bridge.js。其它桥请由自己的DSH按接口适配。

分发包只含机制代码和默认技术参数，没有作者的记忆库、人设和个人规则。
